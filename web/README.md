# Savorum web

This page is for contributors working on the bundled frontend. It is a Solid
application built with TanStack Start in SPA mode, using Park UI controls on
Ark UI and a Savorum-owned Panda CSS theme. It uses the same `/api/v1`
contract as third-party clients.

## Conventions

- **Wording.** The interface uses cooking words, not model names: "earlier
  versions", "categories", "where a recipe came from".
- **Controls.** Use the components in `src/components/ui`; their styles live in
  the recipes under `src/theme/recipes`. Do not substitute a native element or
  override a recipe with `!` at the call site. Choosers use `ui/select`, which
  draws its own list with group names and a tick; the native `<select>` is not
  used, and `<optgroup>` appears only inside a `<datalist>`.
- **Messages.** Anything shown beside the work goes through `Callout` in
  `src/components/status`, or `Problem` and `Notice`. The tone sets both colour
  and icon shape. Do not style error text on a single screen.
- **Translations.** Import `m` from `src/lib/messages`. See
  [interface localization](../docs/contribute/localization.md).
- **Loading and errors.** Use `ResourceState` from the same file for loading
  and refused states. A refresh keeps the last value on screen, and a failed
  resource throws when read, so check the error before reading the value.
- **Dynamic styles.** Styles chosen at run time belong in a `cva` recipe or in
  `staticCss`, not `css(objectRef, objectRef)`: Panda generates CSS by static
  analysis and cannot see classes chosen at run time.
- **Printing.** The print view shows the PDF the server generated, using a PDF
  viewer loaded only on that route. Download and print both use the same
  generated bytes, never the drawn canvases or an HTML version.
- **API calls.** Unwrap results with `unwrap`, `unwrapVersioned`,
  `unwrapItems`, or `expectOk` from `src/api/client`, not by checking
  `result.data` or `result.error` directly.
- **Page layout.** Use the `pageShell` recipe with a named width instead of
  declaring page, title, or back-link styles.
- **Pending changes.** Hold a running change with `createAsyncAction` in
  `src/lib`, or `createKeyedAction` for lists of rows. Pass the thrown error to
  `ChangeError` unchanged, since an `ApiError` carries field-level causes. Read
  the values to send before starting, so the request matches what was on screen.
- **Confirmation.** Use `ConfirmDialog` from `src/components/ui/dialog` before
  irreversible actions. Its cancel control closes the dialog directly.
- **Borders.** `border.subtle` separates items, `border.default` surrounds them,
  and `border.emphasized` marks the one being interacted with. Border tokens are
  never text colours; their contrast is below the 3:1 controls need.
- **Details.** Uncommon fields behind a row open in a `DetailDialog`. Sections
  never nest. The dialog is modal, so follow-up actions belong inside it.

## Develop

Run from `web/`, after the toolchain setup in [Contributing](../CONTRIBUTING.md).
Start the Go server in another terminal from the repository root with
`go run ./cmd/savorum serve --database ./data/savorum.db`.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

The development server proxies API requests to `127.0.0.1:8080`. Add route
files under `src/routes`; TanStack Router updates `src/routeTree.gen.ts`.

Build the production app with:

```bash
pnpm build
```

This regenerates the TypeScript API contract and Panda output, type-checks the
application, creates the SPA shell, and copies static assets into
`../internal/webui/dist` for the Go embed.

The browser tests run against the built executable, which contains both the
frontend and the document renderer. Build it with `just build` from the
repository root, install the browser once with
`pnpm exec playwright install chromium`, and run:

```bash
pnpm test:e2e
```

Choosers have no `<option>` elements, so Playwright's `selectOption` does not
work. Use `choose` (by stored value) or `chooseNamed` (by visible label) from
`e2e/controls.ts`.

## Brand assets

The source artwork lives in `public/brand/`. After updating it, run:

```sh
pnpm run generate:brand
```

Commit the generated icons and rebuild the embedded frontend with
`pnpm run build`.
